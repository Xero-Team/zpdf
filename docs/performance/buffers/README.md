# Transient buffer reuse

Issue: [#142](https://github.com/Xero-Team/zpdf/issues/142). Baseline:
`0e0f8dd3d3e4d12269197758ef5b651e221514b2` (v0.19.0).

The change removes intermediate copies without changing cache budgets,
rendering quality, content separators, partial-output diagnostics or filter
budgets. The existing WASM `rgba()` copying API remains available.

- Page content adopts the first decoded buffer when it is compact; later
  streams retain the existing concatenation and aggregate-limit checks.
- TIFF horizontal prediction modifies compact filter output in place. An
  overallocated decoder buffer follows the previous compact-copy path.
- `PageBitmap.into_rgba()` consumes the bitmap and moves its pixels into the
  binding's return value. The binding still copies to JS-owned storage. The
  browser demo reads dimensions first and never frees a consumed bitmap.

## Measurement scope and protocol

Measured 2026-11-15 in an offline Linux aarch64 Docker environment, kernel
6.8.0-117-generic, Apple CPU vendor (model not exposed), four visible CPUs,
two-CPU quota and 5 GiB memory limit. Rust 1.99.1, release profile,
wasm-bindgen 0.2.129. All data are synthetic and generated by the checked-in
measurement programs; no external PDF corpus is needed.

Native cases run in separate processes in alternating AB/BA pairs, with
11 timing samples per process and an untimed warmup. Each sample drops its
output before the next iteration. Allocation tracking is enabled for a
separate heap observation and disabled during timing. The heap figures count
requested live allocations above the warmed starting point, not RSS, allocator
metadata or transient internal storage used by `realloc`.

Changes are medians of paired process-median ratios. Intervals are percentile
bootstrap 95% intervals (10,000 resamples, deterministic seed 142). The final
review follow-up uses 11 pairs per case and 75 pairs for the pipeline and
plain-Flate controls, fixed before running. PNG's initial 11-pair interval
was inconclusive against a +5% slowdown allowance; a fixed 64 further pairs
retain all observations and yield 75 pooled pairs with identical executable
hashes. No early stopping or input changes were used. Earlier candidates and
their control extensions remain in the evidence and are not pooled with this
revision.

Every final case has identical before/after input and output hashes, no higher
measured peak or retained heap, and an upper timing bound below +5%. These
results establish the measured synthetic scope, not a universal guarantee
about every PDF, platform or browser. In particular, the end-to-end raster
control does not establish a rendering speedup, and the PNG control shows a
small measured slowdown despite its predictor algorithm being unchanged.

The rejected first candidate used `shrink_to_fit()` on overallocated TIFF
buffers. It reduced peak heap in the partial-row case but slowed it by 5.98%
(95% +5.79..+6.41%). Its complete measurements remain in the evidence; they
are not pooled with the final candidate. The shipping fallback deliberately
keeps the previous peak in that case to avoid this tradeoff.

## WASM transfer

Seven alternating process pairs compare the released package's `rgba()` plus
`free()` with the rebuilt package's consuming `into_rgba()` path. Each process
renders a synthetic 3840×2160 page before transfer, records the first transfer
separately, and times 11 subsequent transfers. Rendering and SHA-256 checking
are outside the transfer timer; copying callers free the bitmap afterwards.

- Pixels: 33,177,600 bytes (31.64 MiB), with identical SHA-256 in every run.
- First transfer: old WASM linear memory grows from 37,421,056 to 70,647,808
  bytes; the new path stays at 37,421,056 bytes in all seven processes.
- Median warm transfer: 1.843 ms before, 1.112 ms after. Paired change -38.92%
  (95% -43.80..-37.55%).

The 33,226,752-byte growth avoided is linear-memory capacity, not a measurement
of total browser RSS. Both APIs still allocate the JS-owned output array.

## Reproduction and validation

Use the same lock resolution, toolchain and benchmark source on baseline and
current checkouts. Copy the new example into the baseline checkout, build each
in release mode and archive each executable before building the other:

```sh
cargo build --release -p zpdf-benches --example buffer_memory
target/release/examples/buffer_memory content-single
target/release/examples/buffer_memory content-multi
target/release/examples/buffer_memory content-small
target/release/examples/buffer_memory pipeline
target/release/examples/buffer_memory tiff
target/release/examples/buffer_memory tiff-tail
target/release/examples/buffer_memory tiff-small
target/release/examples/buffer_memory flate
target/release/examples/buffer_memory png

node --expose-gc crates/zpdf-wasm/www/buffer-memory.mjs /path/to/baseline/pkg copy
node --expose-gc crates/zpdf-wasm/www/buffer-memory.mjs /path/to/current/pkg move
```

The Node package directories must be inside an ES-module package (retain
`www/package.json` beside `pkg`). Alternate the archived executables/packages
using the pair counts above. [Raw observations](measurements.jsonl) include
every timing sample, heap measurement and input/output hash. [Provenance](provenance.json)
records source-snapshot, executable, image and dependency-lock identities.
The [initial plan](measurement-plan.json), [first extension](control-extension-plan.json),
[review revalidation plan](review-revalidation-plan.json) and
[PNG extension](review-control-extension-plan.json) record the sample inventory
and retained earlier candidates. The final table uses `measure-native-review`
plus `measure-review-png`; the final WASM result uses `wasm-review`.

The single-stream allocation regression fails on baseline (two large
allocations) and passes after the change (one). Additional tests cover empty
streams, separators, damaged streams, aggregate limits, TIFF wrapping/partial
rows, no-op bit depths, filter chains and byte budgets. Native tests verify
that pixel ownership preserves the allocation; shipped JS/WASM tests verify
pixel equality and independence after subsequent rendering. Formatting,
affected-crate Clippy, native suites, 13 Node tests and 14 Python helper tests
passed in the isolated environment. Full-workspace/platform checks run on the
associated PR.

Review also caught an unnecessary sample copy before rejecting invalid TIFF
row parameters. A counting-allocator regression reproduced one large allocation
before the error and now verifies zero. The private helper's zero/overflow
checks run before compaction; unsupported bit depths retain their existing
no-op behavior. A separate regression reproduced retained slack for predictor
values that wrap to a no-op when narrowed to `u32`; those paths again return
compact output. The 216 parser tests, focused content/diagnostic tests, format
and Clippy checks passed after these fixes. The final native executable and
WASM package were rebuilt and all comparisons above repeated.
