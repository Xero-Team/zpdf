# Support

The zpdf issue tracker is maintained by volunteers. A complete, focused report
is the fastest way to get a useful response.

## Where to ask

- Use the [bug report form](https://github.com/Xero-Team/zpdf/issues/new?template=bug_report.yml)
  for reproducible defects, regressions, crashes, or incorrect output.
- Use the [feature request form](https://github.com/Xero-Team/zpdf/issues/new?template=feature_request.yml)
  for a concrete new capability or improvement.
- Use the [documentation form](https://github.com/Xero-Team/zpdf/issues/new?template=documentation.yml)
  for inaccurate, missing, or unclear documentation.
- Use the [question form](https://github.com/Xero-Team/zpdf/issues/new?template=question.yml)
  for a focused integration or usage question not answered by the README or API
  documentation.
- Report vulnerabilities privately according to [SECURITY.md](SECURITY.md).

Please do not use public issues for credentials, private documents, or embargoed
security information. zpdf currently has no guaranteed response time or private
consulting channel.

## Before filing

Search open and closed issues, test the latest release or current `main`, and
reduce the problem to the smallest example you can share. Include the zpdf
version, environment, exact command or code, expected result, actual result, and
redacted logs. For PDF-specific failures, a minimal redistributable sample often
makes the difference between a report that can and cannot be reproduced.

## Contributing

To contribute, start with [CONTRIBUTING.md](CONTRIBUTING.md). If you use AI
