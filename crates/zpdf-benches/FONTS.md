# Portable font performance gates

Tracking: [#46](https://github.com/Xero-Team/zpdf/issues/46).
Benchmark work package: [#47](https://github.com/Xero-Team/zpdf/issues/47).

The `fonts` Criterion target runs without installed fonts, network access or
private PDFs. It supplements the existing stage/backend/batch targets; it does
not claim to replace the historical real-document corpus.

The Rust dependencies must already be available to Cargo for an offline build.
This repository does not track Cargo.lock. On a clean checkout, generate it
once (`cargo generate-lockfile`, or `cargo generate-lockfile --offline` with a
populated dependency cache) before using the locked measurement runner. Retain
the same lockfile for the comparison; snapshots record its digest.

## Workloads

| Group | Timed work | Setup outside timing |
| --- | --- | --- |
| `fonts/load` | TTF/variable-font construction; CFF PDF parsing and loading; cold/warm twelve-page font loading | Font fixture bytes; pre-opened documents for page-loading cases |
| `fonts/map` | Unicode mapping (Latin, CJK, supplementary, missing) and six legacy decoders, 256 calls per iteration | Loaded font/CMap |
| `fonts/outline` | 256 repeated/unique TTF outlines, CFF outlines, varied TrueType outlines | Face selection and character-to-GID mapping |
| `fonts/pipeline/extract` | Font-cache lookup, content decoding and text extraction from a warm document | Opened document |
| `fonts/pipeline/writer` | Embed, subset and write one page to memory | Text and source font bytes |
| `fonts/pipeline/render` | Fresh CPU renderer, glyph rasterization and output allocation at 96/150/300 DPI | Parsing, font loading and display-list construction |
| `fonts/pipeline/total` | Open in-memory PDF, load fonts, interpret and render | Source PDF construction; excludes file I/O and PNG encoding |
| `fonts/pipeline/render_cff` | Render 256 actual Computer Modern CFF glyphs at three DPIs | Loading the existing Quartz fixture and building its text display list |

The two original geometric fonts are generated by
`crates/zpdf-font/tests/fixtures/generate_coverage_fonts.py` using Python's
standard library. Primary coverage is ASCII, U+4E00..U+4EFF and
U+20000..U+2000F; fallback coverage includes the adjacent CJK ranges and two
supplementary symbols. Space has an advance and intentionally no outline.
These tiny fonts isolate coverage and placement rather than representing the
complexity or typography of production CJK fonts. The existing Quartz CFF and
variable-font fixtures add charstring and variation work. Font-pack and
provider-specific workloads are separate targets with their own identities.

Every text workload verifies extraction, exact glyph IDs, PDF advances and
positions, and an interior ink pixel in every synthetic glyph cell before it
is timed. The CFF fixture checks known GIDs. Correctness tests also distinguish
valid empty glyphs from unsupported characters. CI executes these tests and
all benchmark closures in smoke mode; CI does not enforce 5% timing thresholds.

## Reproducible before/after measurement

Run on an otherwise idle host with the same power settings. The runner first
checks generated fixtures and executes the release correctness tests. It then
asks Criterion for the complete case inventory and measures into a newly
created results directory. A failed run or missing case does not produce a
valid snapshot. Existing evidence files are never overwritten.

```sh
python3 crates/zpdf-benches/tools/font_baseline.py run --output target/font-before.json
# Make the production change without changing benchmark inputs.
python3 crates/zpdf-benches/tools/font_baseline.py run --output target/font-after.json
python3 crates/zpdf-benches/tools/font_baseline.py compare target/font-before.json target/font-after.json
```

Snapshots include toolchain/CPU/OS/compiler flags, fixture and workload hashes,
sample settings, exact case inventory, median confidence intervals, source
revision and a fingerprint including untracked implementation files. Each
snapshot points to its retained raw Criterion results and a copy of the exact
benchmark executable. Changing sources during a run invalidates the snapshot.
Comparison rejects
incomparable hosts, changed workloads, invalid timings and incomplete cases.
A median regression above 5% returns nonzero. Investigate by running independent
repetitions; do not relax the threshold or delete a failing case to get a pass.
An extended suite needs its own baseline before the associated production
change. Retain earlier suite results as additional controls.

On an actively used macOS host, `--scheduler background` applies `taskpolicy -b`
to the benchmark process only and records the policy in the snapshot. This can
help diagnose heterogeneous-core scheduling variance without changing other
applications. It measures that scheduling policy, not foreground application
latency. Both sides must use the same policy; default/background snapshots are
deliberately incomparable. Always validate unchanged-code repeatability before
using a host/policy combination to accept a production change.

```sh
python3 crates/zpdf-font/tests/fixtures/generate_coverage_fonts.py --check
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s crates/zpdf-benches/tools -p 'test_font_baseline.py'
cargo test -p zpdf-benches --test font_workloads
cargo bench -p zpdf-benches --bench fonts -- --test
```

Also run the existing pipeline controls. If the private historical corpus is
unavailable, the explicit portable mode remains useful, but must be reported
as synthetic-only rather than a full-corpus performance result:

```sh
ZPDF_BENCH_SYNTHETIC_ONLY=1 cargo bench -p zpdf-benches --bench stages
```

The original pipeline helpers retain their default one-second warmup,
three-second measurement and cost-adaptive sample count. Explicit Criterion
`--warm-up-time`, `--measurement-time` and `--sample-size` options take priority;
record the chosen values and verify the actual sample files when comparing
controlled runs. Synthetic `stages` covers all nine fixtures, three DPIs and
five stages, including PNG encoding: 135 cases. The deterministic `perf_gate`
tests are complementary correctness checks, not substitutes for these timings.

The CPU-render stage uses Criterion `PerIteration` batching. Renderer creation
and output destruction remain outside timing, and each rendered RGBA page is
released before the next iteration. A full page is a large output: `SmallInput`
retains a sample-dependent number of pages and changes allocation reuse as
Criterion chooses iteration counts. Comparisons across this batching change
are different measurement protocols and must not be pooled. Apply the same
policy to both compared versions and retain older results separately.

## Paired comparison on a variable-load host

Whole-suite runs can drift even with an unchanged executable. The paired
runner uses the archived executables, executes each case in alternating
reference/candidate order and retains all observations. It reports a median
ratio and a reproducible paired bootstrap 95% interval. A performance gate
passes only when the upper interval bound stays below +5%; overlapping bounds
are `inconclusive`, not a pass. Identical executable hashes trigger stricter
calibration in both directions, so an unexplained speedup cannot validate a
noisy measurement setup. Diagnostic subsets never establish a full-suite pass.

```sh
python3 crates/zpdf-benches/tools/font_pair.py \
  target/font-before.json target/font-after.json \
  --output target/font-paired.json --rounds 21
```

`font_pair.py --scheduler default` can explicitly run both archived executables
under default scheduling after a separate identical-binary calibration. It
retains the original snapshot environment and records the actual paired-run
environment. Reports from different scheduling protocols cannot be pooled.

For an interrupted run, first verify that its process has stopped. Invoke the
same command and settings with `--resume path/to/progress.json`. Atomic
checkpoints retain every validated complete pair, and verified completion
markers can recover a pair written just before interruption. An incomplete
pair is remeasured together in a new attempt directory. Legacy files without
process-completion evidence are retained as unverified attempts, never silently
treated as successful timings. Resumption rejects changed executables,
inventories, hosts or measurement settings.

## Provider workloads

The `font_provider` target adds eight cases for registration, duplicates, name
hits/misses, cold/warm supplied-font documents, empty providers on embedded
documents and late registration. It has its own inventory and snapshot; the
original 46-case `fonts` inventory is preserved as the regression control.

```sh
python3 crates/zpdf-benches/tools/font_baseline.py run \
  --bench font_provider --output target/font-provider-initial.json
```

## Font-pack workloads

The `font_packs` target adds fourteen cases: cold and cached decode, raw reuse,
invalid streams, decoded-size rejection, lazy registration, cold/warm name
selection, irrelevant packs, and cold/warm/late-registration/CPU rendering of
real CJK text without installed fonts. The licensed Noto Sans SC fixture has
six code points; see its provenance file for its exact source and SHA-256.
Correctness gates check all four visible Chinese glyphs, extraction, original
PDF widths/positions, CPU ink and all twenty SVG contours.

```sh
python3 crates/zpdf-benches/tools/font_baseline.py run \
  --bench font_packs --output target/font-packs-initial.json
```

Acquisition is deliberately outside Criterion. The host tools test HTTPS
selection, digest pinning, byte bounds, atomic cache publication and offline
reuse. Network/cache acquisition timings must be labeled separately from
decoded-font selection and rendering. The portable tiny-font results do not
establish full CJK font download latency or peak process memory.

## Coverage selection workloads

The `font_coverage` target measures eight provider-level workloads: cold/warm
hits, cold/warm misses, 256 mixed requests, variation selectors, late
registration and lazy pack admission. It checks the selected font and GID
before timing. The original generated fonts remain byte-identical; an
additional 776-byte `coverage-uvs.ttf` tests default and non-default cmap
format-14 sequences. Its generator needs only Python's standard library.

```sh
python3 crates/zpdf-benches/tools/font_baseline.py run \
  --bench font_coverage --output target/font-coverage-initial.json
```

These cases measure the coverage API, not automatic mixed-face page recovery.
That integration remains separate and needs its own placement/rendering gates.

## Authoritative CMap workloads

`font_cmaps` has 31 cases: seven code-to-CID batches, seven segmentation and
Unicode-decoding batches, fourteen embedded/substitute parse-through-CPU-render
pipelines, and three predefined/CFF writer cases. The anchors come from pinned
Adobe sources and keep source code, Unicode, CID and GID distinct. Coverage
includes four-byte GBK2K, HKSCS, supplementary UTF-16, vertical Unicode and
legacy maps, and Identity with a known collection but no ToUnicode.

The original geometric fixtures are unchanged. New original fixtures add
nonuniform widths and a CID-keyed CFF whose charset is not GID identity.
Correctness checks run before timing and verify extraction, glyph identity,
PDF W/W2 placement and visible ink. The generator also emits test-only source
digests for exhaustive verification of all 84 maps and five collections.

Use `--bench font_cmaps` with `font_baseline.py run` or `capture`. Its first
measurement establishes a baseline for the corrected semantics; an older
implementation that maps the wrong CID cannot be a comparable correctness
control. The unchanged original 46 cases and eight provider cases remain
separate regression controls.

## Page, authoring and GPU workloads

The `font_fallback` target adds nine page-level workloads, including mixed
Latin/CJK/supplementary/emoji recovery, fresh and reused page caches, original
extraction, CPU rendering, SVG export, vertical writing, clipping and Forms.
The 256-code text workload verifies each selected face/GID, authoritative PDF
advance/position and every visible cell before measurement. Separate tests
verify late registration, transforms, spacing/TJ, budgets and damaged outlines.

The `font_writer_fallback` target measures multilingual scalar authoring,
single-face authoring and repeated coverage failures. Round-trip tests ensure
TTF/TTC face selection produces self-contained PDFs with correct extraction,
glyph identity and rounded run-boundary advances. The API does not shape or
reorder text; unsupported scalars and variation selectors fail explicitly.

The optional `font_gpu` target has six render/readback workloads: repeated
Latin, unique CJK, mixed supplementary text, vertical text, shear and mirror.
Snapshots and paired observations record and verify the actual adapter.
Feature-gated GPU correctness runs on that adapter; its absence is a failure
for those acceptance tests. Timestamp queries are reported separately from
wall time and are unavailable on the current Apple M5/Metal adapter.

When a paired run is inconclusive, predeclare a fixed extension and retain all
prior observations. `font_pool.py` pools completed reports with identical
executables, measurement settings, environment and inventories. It rejects
duplicate raw sources and incomplete inventories cannot pass. A subset run
alone is diagnostic, even if every selected case passes.
